


# CF 오일온도 예측 — `build_rules()`가 생성하는 규칙

이 함수는 **학습 데이터에서 각 특징(feature)의 온도 도달 확률을 계산하여 CF 규칙을 자동 생성**합니다.

규칙은 크게 두 종류입니다.

1. **단일 특징 규칙(Single Feature Rules)**
2. **복합 특징 규칙(Interaction Rules)**

중요한 점은 규칙을 사람이 직접 지정하는 것이 아니라, **TRAIN 데이터의 통계로부터 자동 생성한다는 것**입니다.

## 1. 단일 특징 규칙

다음 코드에서 규칙을 생성합니다.

```
for name in feature_names:    x = train[name].dropna().to_numpy(dtype=float)    edges = np.unique(        np.quantile(x, np.linspace(0, 1, 9))    )
```

각 특징을 기본적으로 8개 구간으로 나눕니다.

예를 들어 `feature_names`가 다음과 같다고 가정하겠습니다.

```
feature_names = [    "current_temp",    "rate_5",    "rate_10",    "rate_20",    "rate_30",    "rate_60",    "rate_120",    "load",    "power",    "current_mean"]
```

그러면 최대 10종류의 단일 특징 규칙이 만들어집니다.

|규칙|입력 특징|판단 내용|
|---|---|---|
|R1|current_temp|현재 온도에 따른 목표온도 도달 확률|
|R2|rate_5|최근 5분 온도 상승률|
|R3|rate_10|최근 10분 온도 상승률|
|R4|rate_20|최근 20분 온도 상승률|
|R5|rate_30|최근 30분 온도 상승률|
|R6|rate_60|최근 60분 온도 상승률|
|R7|rate_120|최근 120분 온도 상승률|
|R8|load|부하율|
|R9|power|유효전력|
|R10|current_mean|평균전류|

실제 규칙 종류는 `feature_names`에 전달된 항목에 따라 달라집니다.

---

## 2. 규칙은 어떻게 만들어지는가?

예를 들어 현재 오일온도 데이터를 8개 구간으로 나눴다고 가정하겠습니다.

|온도 구간|데이터 수|90℃ 도달 횟수|도달 확률|
|---|---|---|---|
|60~65℃|1,000|10|0.01|
|65~70℃|1,000|20|0.02|
|70~75℃|1,000|50|0.05|
|75~80℃|1,000|100|0.10|
|80~83℃|1,000|200|0.20|
|83~85℃|1,000|400|0.40|
|85~88℃|1,000|700|0.70|
|88℃ 이상|1,000|950|0.95|

_위 수치는 설명을 위한 가상 데이터입니다. 실제 구간은 TRAIN 데이터의 분위수에 따라 결정됩니다._

이때 다음과 같은 규칙이 생성됩니다.

**Rule 1**

```
IF current_temp is 60~65
THEN P(90℃ 도달) ≈ 0.01
```

**Rule 2**

```
IF current_temp is 80~83
THEN P(90℃ 도달) ≈ 0.20
```

**Rule 3**

```
IF current_temp is 88 이상
THEN P(90℃ 도달) ≈ 0.95
```

즉, 각 온도 구간에서 실제로 90℃에 도달한 비율을 학습합니다.

다만 실제 코드에서는 단순한 발생 비율 대신 **스무딩이 적용된 확률**을 사용합니다.

---

## 3. 규칙 확률 계산 방법

다음 코드입니다.

```
lookup = (    stats['sum'] + smoothing * prior) / (    stats['count'] + smoothing)
```

수식으로 표현하면 다음과 같습니다.

\[ \boxed{ P(R_i)=\frac{N_{\text{event}}+\alpha P_0}{N+\alpha} } \]

여기서

- \(N_{\text{event}}\): 해당 구간에서 목표온도에 도달한 횟수
- \(N\): 해당 구간의 전체 데이터 수
- \(P_0\): 전체 TRAIN 데이터의 목표온도 도달 비율
- \(\alpha\): 스무딩 계수, 기본값 30

예를 들어 다음과 같다고 가정하겠습니다.

- 해당 구간 데이터: 100개
- 90℃ 도달: 40개
- 전체 데이터의 90℃ 도달 비율: 0.10
- smoothing: 30

그러면

\[ P(R_i)=\frac{40+30(0.1)}{100+30} \]\[ \boxed{P(R_i)=0.3308} \]

스무딩을 적용하지 않으면 확률은 0.4입니다.

스무딩은 표본이 적은 구간의 확률이 지나치게 높거나 낮아지는 것을 완화합니다.

# 4. 복합 특징 규칙

현재 코드에서 가장 중요한 부분입니다.

```
if 'bin_current_temp' in train and 'bin_rate_30' in train:    joint = [        'bin_current_temp',        'bin_rate_30'    ]
```

이 코드는 다음 두 가지 특징을 결합합니다.

- 현재 오일온도
- 최근 30분 온도 상승률

따라서 다음과 같은 규칙을 생성합니다.

\[ \boxed{P(T_{\text{future}}\ge90\mid T_{\text{current}},R_{30})} \]

예를 들어 다음과 같습니다.

|현재온도|30분 상승률|90℃ 도달 확률|
|---|---|---|
|75℃|낮음|0.05|
|75℃|높음|0.30|
|80℃|낮음|0.15|
|80℃|높음|0.60|
|85℃|낮음|0.45|
|85℃|높음|0.90|

_예시 수치입니다._

이것을 IF–THEN 규칙으로 표현하면 다음과 같습니다.

```
RULE 1

IF current_temp = HIGH
AND rate_30 = HIGH

THEN probability(90℃) = 0.90
```

```
RULE 2

IF current_temp = HIGH
AND rate_30 = LOW

THEN probability(90℃) = 0.45
```

단일 특징 규칙에서는 현재온도가 같으면 같은 온도 기반 확률을 사용하지만, 복합 규칙에서는 상승률에 따라 서로 다른 확률을 계산할 수 있습니다.

**현재 코드에서 생성하는 복합 규칙은 `current_temp × rate_30` 한 종류뿐입니다.**

---

## 5. 규칙은 총 몇 개 생성되는가?

특징이 10개이고 각각 8개 구간으로 나뉜다면 다음과 같습니다.

|규칙 종류|최대 구간 조합|
|---|---|
|단일 특징 규칙|10 × 8 = 80|
|복합 특징 규칙|8 × 8 = 64|
|**합계**|**144**|

단, 이것은 가능한 최대 구간 조합 수입니다.

실제로는 다음 조건에 따라 규칙 수가 줄어듭니다.

```
stats = stats.loc[    stats['count'] >= min_count]
```

기본적으로 데이터가 20개 미만인 구간은 제외됩니다.

또한 특징의 값이 중복되어 분위수 경계가 합쳐지면 구간 수가 8개보다 적어질 수 있습니다.

---

## 6. 현재 코드의 중요한 한계

현재는 다음과 같은 복합 규칙이 없습니다.

```
current_temp × rate_5
current_temp × rate_60
current_temp × rate_120

current_temp × load
current_temp × power

rate_30 × load
rate_30 × power
```

특히 **90℃를 120분 전에 예측하려면 장기 온도 변화와 부하율의 관계를 학습하는 것이 도움이 될 수 있습니다.**

예를 들어 다음과 같은 복합 규칙을 추가할 수 있습니다.

|복합 규칙|목적|
|---|---|
|온도 × 5분 상승률|단기 과열 감지|
|온도 × 30분 상승률|중기 온도 변화|
|온도 × 60분 상승률|장기 상승 추세|
|온도 × 120분 상승률|장시간 과열 예측|
|온도 × 부하율|운전 부하에 따른 온도 변화|
|상승률 × 부하율|고부하 상태의 온도 상승|
|온도 × 유효전력|전력 소비와 온도 관계|

다만 복합 규칙을 무조건 많이 추가하면 데이터가 부족한 구간이 증가하고 과적합이 발생할 수 있습니다.

따라서 검증 데이터에서 실제로 성능이 향상되는 규칙만 선택하는 것이 좋습니다.

## 7. 이 함수가 반환하는 결과

마지막 코드입니다.

```
return matrices, list(evidences), prior
```

세 가지 값을 반환합니다.

**① matrices**

Train, Validation, Test 각각의 확신도 행렬입니다.

예를 들어 다음과 같은 형태입니다.

\[ M= \begin{bmatrix} 0.2 & 0.3 & 0.4 & 0.5\\ 0.4 & 0.6 & 0.7 & 0.8\\ 0.7 & 0.8 & 0.9 & 0.9 \end{bmatrix} \]

각 행은 하나의 데이터, 각 열은 하나의 규칙에 해당합니다.

**② list(evidences)**

생성된 규칙의 이름입니다.

```
[    'current_temp',    'rate_5',    'rate_10',    'rate_30',    'load',    'power',    'temp_x_rate30']
```

**③ prior**

TRAIN 데이터 전체에서 목표온도에 도달한 비율입니다.

예를 들어

```
prior = 0.12
```

라면 전체 학습 데이터의 12%가 해당 목표온도에 도달했다는 의미입니다.

## 8. 메가콤 프로젝트에서 중요한 개선 방향

현재 알고리즘은 **데이터 기반 확률 규칙을 생성하고 이를 결합하는 방식**입니다.

그러나 이 함수 자체가 최종 확신도를 계산하는 것은 아닙니다. 규칙별 확률을 행렬로 반환하며, 이후 별도의 가중치 결합 과정이 필요합니다.

85℃와 90℃의 예측 성능을 높이려면 다음 두 가지를 우선 검토하는 것이 좋습니다.

**첫째**, 현재 30분 상승률만 사용하는 복합 규칙을 5·30·60·120분 상승률까지 확대합니다.

**둘째**, 목표온도별로 동일한 규칙을 무조건 적용하기보다 검증 데이터에서 효과적인 규칙을 선택합니다.

예를 들어 90℃의 120분 예측에서는 `current_temp × rate_120`이 유용할 수 있지만, 10분 예측에서는 `current_temp × rate_5`가 더 유용할 수 있습니다. 이는 실제 데이터로 확인해야 합니다.

**질문:** 다음 단계에서 `build_rules()`를 수정하여 **80℃, 85℃, 90℃ 각각에 대해 10~120분 예측시간별로 최적 복합 규칙을 자동 선택하는 방식**으로 개선하시겠습니까?

2. A형 — 정확히 N분 후 예측
예를 들어 120분 후 오일온도가 90℃ 이상인지 예측합니다.

$$
P(T_{t+120}\ge90^\circ C)
$$


 C)


예측시간은 10, 20, 30, 60, 90, 120분입니다.

80℃, 85℃, 90℃에 대한 예측 결과를 각각 계산합니다.

3. B형 — N분 이내 목표온도 도달 예측
예를 들어 앞으로 120분 동안 한 번이라도 90℃에 도달하는지 예측합니다.



$$
P\left(\max_{1\le k\le120}T_{t+k}\ge90^\circ C\right)
$$


 C)
사용 방법:

```python
import pandas as pd
import cf_B

df = pd.read_csv("남양금속 11호기.csv", encoding="cp949")

result = cf_B.calculate_all(df)

print(result)
```

A형과 B형의 차이는 다음과 같습니다.

2. 현재 cf.py에서 발견한 문제
첨부된 코드에서 다음 사항을 확인했습니다.

문제 ① 온도 변화율을 5분만 사용
현재 코드:

df["temp_5min_ago"] = (
    df["current_temp"].shift(5)
)

df["temp_rate"] = (
    df["current_temp"] - df["temp_5min_ago"]
) / 5.0

현재는 5분 동안의 온도 변화율만 사용합니다.

그러나 120분 후 온도를 예측하려면 장시간의 온도 변화 패턴도 필요합니다.

개선 방법

for t in [5, 10, 20, 30, 60, 120]:

    df[f"temp_rate_{t}"] = (
        df["current_temp"]
        - df["current_temp"].shift(t)
    ) / t

이렇게 하면 다음과 같은 특징을 생성할 수 있습니다.

특징	의미
temp_rate_5	최근 5분 온도 변화율
temp_rate_10	최근 10분 온도 변화율
temp_rate_20	최근 20분 온도 변화율
temp_rate_30	최근 30분 온도 변화율
temp_rate_60	최근 60분 온도 변화율
temp_rate_120	최근 120분 온도 변화율
이러한 다중 시간 특징은 85℃와 90℃ 예측에 도움이 될 가능성이 있습니다.

단, 실제 데이터가 정확히 1분 간격인지 확인해야 합니다. 그렇지 않으면 shift(t) 대신 실제 시간 기준으로 계산해야 합니다.

문제 ② 각 증거를 독립적으로 계산
현재 CF 알고리즘은 다음과 같은 특징을 개별적으로 분석합니다.

하지만 실제 오일온도는 여러 운전 조건이 복합적으로 작용한 결과입니다.

예를 들어 다음 두 상황을 비교해 보겠습니다.

3. 가장 중요한 문제: 학습 및 검증 방법
현재 코드에서는 데이터를 시간순으로 70%와 30%로 나눕니다.

TRAIN_RATIO = 0.70

그러나 이후 검증 데이터로 가중치를 최적화하고, 동일한 검증 데이터에서 F1 Score가 최대가 되는 임계값을 선택한 다음, 다시 그 데이터로 최종 성능을 평가합니다.

이 경우 성능이 실제보다 높게 측정될 가능성이 있습니다.

따라서 다음과 같이 변경하는 것이 필요합니다.

데이터	비율	목적
Train	60%	CF 규칙 생성
Validation	20%	가중치 및 임계값 최적화
Test	20%	최종 성능 평가
또한 미래 온도를 예측하는 시계열 문제이므로 각 데이터 구간 사이에 예측시간에 해당하는 간격을 두어 학습과 평가 사이의 정보 누출을 방지하는 것이 좋습니다.

4. 가장 추천하는 방법: 90℃ 특성 분석 + 규칙 개선
현재 CF 모델에 다음 절차를 적용하는 것을 권장합니다.
전체 컴프레서 데이터

90℃ 도달 / 미도달 데이터 분리

온도 · 상승률 · 부하율 · 전력 · 전류 특징 비교

90℃ 위험 구간에 대한 복합 규칙 생성

시간순 검증 데이터로 성능 평가


특히 현재 CF 코드에서는 오일온도, 상승률, 부하율 등을 각각 구간화하여 확률 규칙을 생성하고 결합합니다. 그런데 90℃에 도달하는 현상은 단일 변수보다 현재 온도와 온도 상승률의 조합에 의해 더 잘 설명될 수 있습니다.
따라서 다음과 같은 복합 규칙을 추가하는 것이 유망합니다.
\[
CF_{90}=f(T,\ R,\ L,\ P,\ I)
\]

예를 들어 현재 온도 구간 × 상승률 구간에 대한 90℃ 도달 확률을 별도로 학습하는 것입니다.

0.90은 실험 결과가 아닌 목표값입니다.
검증에서는 반드시 다음을 지켜야 합니다.
1. 학습 데이터와 검증 데이터를 시간순으로 분리합니다.
2. 합성 데이터는 학습 구간에만 생성합니다.
3. 동일한 검증 데이터에서 개선 전후 F1-score를 비교합니다.
4. 10~300분 예측 시간별로 각각 성능을 확인합니다.
또한 현재 코드가 검증 데이터에서 가중치와 최적 임계값을 모두 결정한 뒤 같은 데이터로 F1-score를 계산한다면, 성능이 낙관적으로 나타날 수 있습니다. 학습·튜닝·최종 테스트를 별도로 분리하는 것이 좋습니다.

결론
90℃ 예측 성능 개선을 위해 유사 데이터를 생성하는 것은 가능하지만, 먼저 90℃ 도달 사례의 특징을 분석하고 복합 CF 규칙을 추가하는 방법을 추천합니다.
특히 10분, 30분, 1시간, 3시간 후의 90℃ 도달 특성이 서로 다를 수 있으므로 시간별 분석이 중요합니다.
다음 단계로 현재 cf.py에 90℃ 도달 데이터의 특징 분석, 클래스 불균형 확인, 복합 규칙 생성, 개선 전후 F1-score 비교 기능을 추가할 수 있습니다.

def cal_cf(self):

    algorithm = self.CmBOX_algorithm.currentText()

    predict_time = self.CmBOX_predictTime.currentText()

    time_map = {
        "5시간": 300,
        "4시간": 240,
        "3시간": 180,
        "2시간": 120,
        "1시간": 60,
        "30분": 30,
        "20분": 20,
        "10분": 10
    }

    predict_min = time_map[predict_time]

    try:
        if algorithm == "CF-rulebase":

            result = cf.calculate_cf(
                self.df.copy(),
                predict_min=predict_min
            )

            print("Prediction time:", predict_min)
            print("CF result:", result)

    except Exception as e:
        print("Error:", e)

4. 중요한 점: 10분 예측과 5시간 예측은 성능이 다릅니다
예측 시간이 길어질수록 미래의 운전 상태가 달라질 가능성이 커집니다. 따라서 5시간 예측은 10분 예측보다 일반적으로 어려울 수 있습니다.

현재 CF 모델은 현재 온도, 5분 온도상승률, 부하율, 전력 등을 사용합니다. 장기 예측에서는 최근 30분~1시간의 온도 추세, 운전 상태, 부하 변화 등을 추가하는 것이 도움이 될 수 있습니다.

또한 예측 시간을 바꿀 때마다 결과 CSV 파일 이름에 시간을 포함하는 것이 좋습니다.

result_file = (

이렇게 하면 여러 예측 시간의 결과를 덮어쓰지 않고 비교할 수 있습니다.

PDF로 변환
df["future_temp"] = (
    df["current_temp"].shift(-PREDICT_MIN)
),,,이 코드는 어디에 들어가는가?
이 코드는 cf.py 파일의 calculate_cf() 함수 내부, 14번 항목인 10분 후 실제 온도 부분에 들어갑니다.

이미 업로드하신 cf.py에 해당 코드가 있으므로 새로 추가할 필요 없이 기존 코드를 그대로 사용하면 됩니다.

1. cf.py의 기존 코드
# ============================================================
# 14. 10분 후 실제 온도
# ============================================================

df["future_temp"] = (
    df["current_temp"].shift(-PREDICT_MIN)
)

이 부분은 13. 온도 상승률 계산 다음, 15. 목표 온도 도달 여부 계산 전에 위치합니다.

2. 수정해야 할 부분은 함수 시작 부분입니다
기존:

def calculate_cf(df):

    PREDICT_MIN = 10

수정:

def calculate_cf(df, predict_min=10):

    PREDICT_MIN = int(predict_min)

이렇게 하면 14번 코드에서 PREDICT_MIN 값을 자동으로 사용합니다.

3. megacom.py에서 호출
# 5시간 후 예측
result = cf.calculate_cf(self.df, predict_min=300)

# 1시간 후 예측
result = cf.calculate_cf(self.df, predict_min=60)

# 10분 후 예측
result = cf.calculate_cf(self.df, predict_min=10)

단, 위 예제는 데이터가 1분 간격으로 기록된 경우입니다.

정리하면: cf.py의 14번 코드는 수정할 필요가 없으며, calculate_cf() 함수의 매개변수와 PREDICT_MIN 설정만 변경하면 됩니다.

참고로 14. 10분 후 실제 온도라는 주석은 14. 선택한 예측 시간 후 실제 온도로 변경하는 것이 좋습니다.
