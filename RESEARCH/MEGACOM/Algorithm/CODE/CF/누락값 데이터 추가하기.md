칼렴에서 기록이 누락되는 부분이 많다...누락없이 시간을 찾아서 기록할수 잇는가

네. **`oil_temp_actual`에 실제 측정온도가 누락되는 문제를 개선하도록 CF 프로그램을 수정했습니다.**

기존 프로그램에서 누락이 발생하는 주요 원인은 다음 두 가지입니다.

1. **측정시간 허용오차가 ±5초로 너무 좁음:** 예측 대상 시각과 실제 측정 시각이 5초 이상 차이 나면 실제온도를 입력하지 않습니다.
2. **매번 오래된 300건만 검사:** 실제 측정값이 없는 오래된 데이터가 계속 조회되면 그 뒤에 있는 데이터까지 검사하지 못할 수 있습니다.

이번 수정에서는 이 두 가지 문제를 개선했습니다.

## 1. 수정된 프로그램 다운로드

기존 CF 예측 기능은 유지하면서 실제온도 조회 기능을 수정했습니다.

## 2. 변경된 기능

|항목|기존|수정|
|---|---|---|
|실제온도 조회|±5초|기본 ±30초|
|한 번에 조회하는 데이터|300건|최대 6,000건|
|오래된 데이터 때문에 조회가 막히는 문제|발생 가능|페이지 이동 방식으로 개선|
|실제온도 검색|`ai_data.io003`|동일|
|가장 가까운 측정값 선택|지원|유지|
|`oil_temp_actual` 자동 입력|지원|유지|
|기존 실제온도 덮어쓰기|안 함|유지|
|`prediction_model`|CF|CF|

예측 대상 시각의 정확한 측정값이 없으면 ±30초 이내에서 가장 가까운 실제 측정값을 사용합니다.

**단, 원본 `ai_data`에 해당 시간대의 측정값이 전혀 없다면 `NULL`이 남습니다.** 측정값이 존재하지 않는 경우까지 임의의 온도를 만들어 입력하지는 않습니다.

## 3. 기존 누락 데이터 일괄 보정

먼저 다음 명령으로 실행하세요.

```
python cf_realtime_11_cf_temperature_actual_fixed.py --once --actual-only
```

이 명령은 새로운 CF 예측을 수행하지 않고, 기존 `ai_oiltemp`의 실제온도가 누락된 행을 찾아 보정합니다.

누락 데이터가 많다면 다음과 같이 검사량을 늘릴 수 있습니다.

```
python cf_realtime_11_cf_temperature_actual_fixed.py --once --actual-only --actual-batch-size 500 --actual-max-batches 100
```

이 경우 최대 50,000개 예측 행을 검사합니다.

## 4. 5초 간격 자동 실행

기존처럼 실시간 예측과 실제온도 보정을 함께 실행하려면 다음 명령을 사용하세요.

```
python cf_realtime_11_cf_temperature_actual_fixed.py --interval 5
```

프로그램은 다음 순서로 작동합니다.

① 최신 측정 데이터로 CF 예측 수행

② `ai_oiltemp`에 예측온도 저장

③ `prediction_target_time`이 지난 데이터 조회

④ `ai_data`에서 해당 시각과 가장 가까운 실제 오일온도 검색

⑤ `oil_temp_actual` 업데이트

## 5. 누락된 데이터 확인 SQL

현재 실제온도가 누락된 건수를 확인하려면 다음 SQL을 실행하세요.

```
SELECT
    prediction_horizon_min,
    COUNT(*) AS total_count,
    SUM(oil_temp_actual IS NOT NULL) AS completed_count,
    SUM(oil_temp_actual IS NULL) AS missing_count
FROM airpredict.ai_oiltemp
WHERE device_id = 'R00015'
  AND prediction_model = 'CF'
  AND prediction_target_time <= NOW()
GROUP BY prediction_horizon_min
ORDER BY prediction_horizon_min;
```

이 SQL은 MySQL 서버의 `NOW()`가 예측 대상 시각과 같은 시간대라는 전제입니다.

### 확인할 사항

수정한 프로그램은 Python 구문 검사를 완료했지만 실제 MySQL 데이터에 대한 실행 검증은 아직 하지 않았습니다.

**권장 순서:** 먼저 `--once --actual-only`로 기존 누락 데이터를 보정하고, 위 SQL을 실행해 누락 건수가 얼마나 감소했는지 확인하세요.

이후에도 누락이 많다면 `ai_data.input_time`과 `prediction_target_time`의 시간대 및 저장 형식을 확인해야 합니다.
