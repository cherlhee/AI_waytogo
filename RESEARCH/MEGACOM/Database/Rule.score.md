첨부하신 **「룰베이스 AI 판단 기준」**과 **「AI-TD6 데이터베이스 설계서」**를 기준으로 `ai_data`에서 데이터를 조회하고, 룰베이스 판정 결과를 `ai_analysis`에 저장하는 Python 코드를 작성했습니다.

## 1. Python 코드 다운로드

코드는 다음 5개 테이블을 사용합니다.

|테이블|용도|
|---|---|
|`ai_data`|5초 간격 센서 데이터|
|`st_comcode_set`|설비별 전압·압력·교체주기 기준|
|`ai_current_std`|주파수별 평균전류 기준|
|`ai_oiltemp_std`|주파수·외부온도별 오일온도 기준|
|`ai_analysis`|룰베이스 분석 결과 저장|

## 2. 룰베이스 판단 기준

첨부된 기준서에 따라 다음 항목을 구현했습니다.

|항목|판단 기준|점수|
|---|---|---|
|유량계 온도|30℃ 미만 / 30~35 / 35~40 / 40~45 / 45℃ 이상|0/40/50/60/70|
|전압|기준전압 대비 편차 5% / 7%|0/40/70|
|평균전류|기준전류 대비 편차 5% / 10% / 15%|0/40/60/70|
|토출압력|5초 이내 3bar 이상 변화|70|
|오일온도|기준온도 대비 편차 5% / 10%|0/40/70|
|소모품 교체주기|기준시간의 90% / 100%|0/40/70|
|선간전압 불균형|전압 차이 비율|0/40/70|
|전류 불균형|최대·최소 전류 차이 비율|0/40/70|

시계열 변화점수(`io902`)는 별도의 AI 예측 결과가 필요하므로 현재 코드에서는 NULL로 처리합니다. 룰베이스 AI 판단 기준 (1)

## 3. 실행 방법

먼저 PowerShell에서 DB 연결 정보를 환경변수로 지정합니다.

```
$env:DB_HOST = "121.181.35.7"
$env:DB_PORT = "3307"
$env:DB_USER = "mega_admin"
$env:DB_PASSWORD = "실제비밀번호"
$env:DB_NAME = "airpredict"
```

최근 2,000건을 분석하려면 다음 명령을 실행합니다.

```
python rulebase_ai_analysis.py --once --limit 2000
```

특정 설비만 분석하려면 다음과 같이 실행합니다.

```
python rulebase_ai_analysis.py --once --device-id R00015
```

실제 DB에 저장하지 않고 계산 결과만 확인할 수도 있습니다.

```
python rulebase_ai_analysis.py --once --limit 10 --dry-run
```

## 4. ai_analysis 저장 구조

예를 들어 유량계 온도가 38℃라면 다음과 같이 계산합니다.

```
io045 = 38.0grade_045 = 50alarm_045 = "5"
```

현재 코드에서는 알람단계를 다음과 같이 매핑했습니다.

|점수|알람단계|
|---|---|
|0|`0` 정상|
|40~60|`5` 주의|
|70|`9` 경고|

다만 설계서에는 `0:정상, 5:경고, 9:알람`으로 정의되어 있어, **주의·경고와 알람코드의 대응은 운영 기준 확인이 필요합니다.**

## 5. 실제 운영 전 확인할 사항

코드에는 다음 사항이 반영되어 있습니다.

- `ai_data`의 `deviceId` 컬럼명 사용
- `ai_analysis`의 실제 시간 컬럼이 `judge_time` 또는 `input_time`인지 확인
- 동일 기본키에 대해 `ON DUPLICATE KEY UPDATE` 적용
- 전류값이 0이거나 누락되면 해당 전류 기반 판정을 수행하지 않음
- 기준값이 없으면 임의로 정상 처리하지 않고 NULL 저장

**추가로 확인해야 할 부분이 있습니다.**

첫째, 기준서에서 선간전압 불균형의 7~10% 구간이 정상과 주의에 중복되어 있습니다. 현재 코드는 7% 이상을 주의로 처리했습니다.

둘째, `ai_oiltemp_std`의 기준값은 주파수와 외부온도가 정확하게 일치할 때 조회합니다. 실제 기준 테이블이 온도 구간별로 작성되어 있다면 조회 방식을 수정해야 합니다.

셋째, 현재 반복 실행 모드는 5초마다 최근 2,000건을 다시 조회합니다. 실제 운영에서는 **마지막으로 처리한 `input_time` 이후의 신규 데이터만 조회하도록 변경하는 것이 효율적**입니다.

현재 코드는 실제 DB에서 검증하지 않은 상태입니다. 먼저 `--dry-run`으로 계산 결과를 확인한 다음, 실제 저장을 진행하는 것이 좋습니다.
